# Invoice Intelligence: rules for working in this repo

A pipeline that turns invoice PDFs (including scanned ones) into validated JSON.
Every extracted field carries **provenance**: page, verbatim quote, and confidence.
The repo is a portfolio piece that clients read before hiring, so clarity beats cleverness.

## Hard architectural constraints (non-negotiable)

1. **The LLM extracts and cites. It never decides and never calculates.**
   - The LLM returns *strings and locations only*: `value_text`, `page`, `line_start`, `line_end`.
   - Parsing (amounts, dates, tax IDs), arithmetic, confidence scores, tax-scheme
     detection, adjustment kinds, and every pass/fail check are deterministic Python.
   - The LLM must not fill a missing printed value by computing it (e.g. summing line items
     to produce a subtotal). Absent stays absent.
   - If you find yourself asking the LLM to do math or make a judgment, the design is wrong.
2. **Pydantic models in `app/models.py` are the contract.** Change the schema first;
   everything else conforms. There are two layers: the wire schema (what the LLM returns, strings
   only) and the domain schema (typed, built by Python after verification).
3. **Ground truth is hand-written by the human owner.** `tests/fixtures/expected/*.json`
   is never generated by an LLM or derived from generator data. Do not write or "fill in"
   these files. Only `_TEMPLATE.json` is maintained by tooling.
4. **Graceful degradation.** A missing field is `None` with a `missing_reason`, never a guess.
   A value whose citation cannot be verified against the page text is rejected (→ `None`).
   Low confidence is shown, never hidden.
5. **No secrets in code.** The API key comes from the environment (`.env`, gitignored).
6. **Minimal dependencies.** Every package in `requirements*.txt` has a one-line
   justification in README. Prefer the stdlib (e.g. `difflib` over rapidfuzz). Ask before adding one.

## Conventions
- Money is `Decimal`, serialized to JSON as **strings**. Never `float`.
- Pages and lines are **1-indexed**.
- Functions that depend on "today" take a `today: date` parameter (no hidden clock).
- **Every file starts with a header comment block**: what it does (one sentence), what
  goes in, what comes out, and the most likely reason it would fail. Python files use
  the module docstring; Markdown uses an HTML comment. JSON can't hold comments, so
  JSON files are documented in the README of their directory.

## Out of scope unless the owner explicitly approves
Auth, a database beyond JSON files on disk, multi-tenancy, Docker, CI/CD, other document
types, job queues (FastAPI `BackgroundTasks` is the ceiling), and frontend frameworks.

## Layout
```
app/models.py       Pydantic contract (wire + domain + flags + result envelope + ground-truth format)
app/extract.py      PDF -> line-numbered page text (pdfplumber; Tesseract OCR fallback per page)   [M2]
app/llm.py          Anthropic tool-use call behind a Protocol (mockable)                           [M3]
app/parse.py        Deterministic parsing of amounts / dates / tax IDs                             [M3]
app/provenance.py   Quote verification + deterministic confidence                                  [M3]
app/validate.py     Business checks -> ValidationFlag list                                         [M4]
app/pipeline.py     run(pdf_bytes) -> ExtractionResult                                             [M5]
app/storage.py      JSON files under DATA_DIR                                                      [M5]
app/main.py         FastAPI: POST /extract (202), GET /result/{id}                                 [M5]
static/review.html  Vanilla JS review UI                                                           [M6]
scripts/generate_fixtures.py   Deterministic synthetic invoice PDFs
scripts/evaluate.py            Accuracy harness                                                    [M7]
tests/fixtures/pdfs/           Generated PDFs (committed)
tests/fixtures/expected/       Hand-written ground truth (owner only)
tests/fixtures/private/        Real invoices, gitignored (PII)
```

## Commands
```
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python scripts/generate_fixtures.py     # regenerate fixture PDFs (byte-identical)
.venv/bin/pytest
```
Tested on Python 3.14.3 (macOS x86_64): all dependencies install from prebuilt wheels.
OCR (from M2) also needs the Tesseract binary: `brew install tesseract`.
